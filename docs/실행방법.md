# Clarix 실행방법 설명서

서비스명: Clarix  
기술스택: Java 21, Spring Boot 3.5, Thymeleaf, Spring Data JPA, MySQL 8, Spring Security

## 1. 사전 준비

- Java 21
- MySQL 8.x
- 프로젝트 루트: `maum_med`

## 2. MySQL 데이터베이스 생성

MySQL 콘솔에서 아래 SQL을 실행합니다.

```sql
CREATE DATABASE clarix CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'clarix'@'localhost' IDENTIFIED BY 'clarix1234';
GRANT ALL PRIVILEGES ON clarix.* TO 'clarix'@'localhost';
FLUSH PRIVILEGES;
```

이미 계정이 있다면 `clarix` 데이터베이스에 대한 권한만 확인하면 됩니다.

## 3. 환경변수 설정

```bash
cd patient-api
export MYSQL_HOST=localhost
export MYSQL_PORT=3306
export MYSQL_DATABASE=clarix
export MYSQL_USER=clarix
export MYSQL_PASSWORD=clarix1234
```

IntelliJ를 사용하는 경우 Run Configuration의 Environment variables에 같은 값을 입력합니다.

## 4. 서버 실행

```bash
./gradlew bootRun
```

정상 실행 후 브라우저에서 아래 주소로 접속합니다.

```text
http://localhost:8081
```

## 5. 자동 생성 데이터

첫 실행 시 `DemoDataInitializer`가 MySQL에 데모 데이터를 자동 생성합니다.

- 병원 8개
- 관리자, 의사, 간호사, 검사기사, 접수, 환자 계정
- 처방, 복약 기록, 감정 기록, 식사/운동 기록
- PHQ-9 검사 결과
- SOAP 임상 노트

`users` 테이블에 데이터가 이미 있으면 기존 데이터를 보존하기 위해 자동 시드를 건너뜁니다.

## 7. 주요 기능 확인 순서

1. 환자 계정으로 로그인합니다.
2. `/patient/`에서 오늘 복약, 감정, 식사, 운동 기록을 입력합니다.
3. `/patient/assessment`에서 PHQ-9 문항을 제출합니다.
4. `/patient/onboarding`에서 복용 약을 추가하거나 중단합니다.
5. 의사 계정으로 로그인합니다.
6. `/doctor/`에서 위험 환자 목록과 7일 순응도를 확인합니다.
7. `/doctor/patient/{id}`에서 timeline JSON 차트, SOAP 작성, 처방 추가를 확인합니다.
8. 접수/간호사/관리자 계정으로 역할별 화면 접근 제어를 확인합니다.

## 8. 과제 요구사항 대응

| 요구사항 | 구현 |
|---|---|
| 반응형 웹 Frontend | Thymeleaf, CSS media query, 모바일 환자 화면, 데스크톱 의료진 화면 |
| Spring Boot Backend | Controller, Service, Repository 계층 |
| DTO 기반 데이터 처리 | `com.clarix.dto` 패키지와 `@ModelAttribute` 바인딩 |
| MySQL 기반 CRUD | `application.properties`, JPA Entity, JpaRepository |
| REST API / JSON | `/doctor/patient/{id}/timeline`, `/doctor/drug-check`, `/doctor/patient/{id}/llm-soap` |

## 9. 문제 해결

| 증상 | 해결 |
|---|---|
| 8081 포트 사용 중 | `lsof -ti :8081 | xargs kill -9` 실행 후 재시도 |
| MySQL 접속 실패 | DB 생성, 계정 권한, `MYSQL_*` 환경변수 확인 |
| 테이블이 생성되지 않음 | `spring.jpa.hibernate.ddl-auto=update` 확인 |
| 데모 데이터가 보이지 않음 | `users` 테이블이 비어 있는지 확인 후 재실행 |
| 로그인 실패 | 데모 계정 이메일/비밀번호를 그대로 입력 |
